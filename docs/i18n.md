# Interface languages (i18n)

The web interface supports Simplified Chinese (`zh`) and English (`en`). Users switch with the 中 / EN toggle in the
navigation bar (saved as `ui_language`, applied on reload). AI-generated text follows `ai_language` (empty = follow the
interface language).

## Keys

Use **semantic keys** of the form `module:dotted.name` for all new text:

```python
t("search:filter.author", value=name)            # Python   (from .i18n import t)
```
```jinja
{{ _('dashboard:tile.notes_unsynced', n=count) }}  {# Jinja #}
```
```js
tr('usage:session.summary', { turns: 3, unit: L.unit, calls: 12 })   // page scripts
```

Translations live in `src/Pageboygent/locales/{zh,en}.json`, nested by module:

```json
{ "search": { "filter": { "author": "Author: {value}" } } }
```

Lookup order for a semantic key: current language → Chinese → the key itself.

Most existing text still uses the **Chinese source string as the key** (`t("新文章")`, stored at the top level of
`en.json`). This is a transition format: when touching that text, prefer moving it to a semantic key. Never reuse a
Chinese-string key for a place that needs a different English translation; give it a semantic key instead.

Rules:

- Put variables in placeholders (`{n}`), never concatenate translated fragments around numbers or punctuation.
- Data stored in the database or in JSON files (reasons, notes, logs) should be stored as codes/numbers and turned into
  text at display time, so it follows the current language.
- Prompts sent to the LLM are not translated; they contain `〔回答语言〕` / `〔研究领域〕` placeholders filled from
  `ai_language` / `research_field`.

`src/Pageboygent/tests/test_i18n.py` fails if a key used in code has no translation, if a semantic key is missing from
either language, or if a translation introduces placeholders the source doesn't have.
